# 自定义剧情专题问题生成

## 目标

在“问派蒙”右侧的“选择剧情专题”中新增“自定义专题”。玩家可输入一个剧情名称或关键词，让派蒙围绕该词生成 4–5 个问题；它复用当前地区、玩家进度、剧透偏好和关注方向，只有原本预设专题的范围词替换为玩家输入。

## 交互

1. 地区选择与预设专题按钮保持原样；专题列表最后增加一张“自定义专题”选择卡。
2. 选中后展示输入框，接受 2–60 个字符。空值或过短时生成按钮不可用，并提示输入剧情名、角色或关键词。
3. 输入框下方显示与已输入内容匹配的预设关键词。按 Tab 且存在候选项时，补全第一项；鼠标/触屏点击候选项也可填入。正常 Tab 行为在没有候选项时保留。
4. 初始预设词覆盖高频、资料较丰富的内容，例如：戴因斯雷布、坎瑞亚、深渊、旅行者血亲、斯卡拉姆齐、魔女会、天理、虚假之天、龙王、世界树、法涅斯、水仙十字结社。
5. 点击“让派蒙想几个问题”后，生成区仍展示 4–5 个可快速提问的问题。成功状态标记为“派蒙刚想到的问题”。

## 数据与服务端

- 请求继续包含当前预设 `topicId`，它是地区范围、限流、缓存基准和兜底题目的来源。
- 新增可选 `customTopic` 字段：服务端验证、裁剪并规范化后，将其作为临时生成专题的标题与范围；不写入 `questionSuggestionTopics` 数据表，也不把用户词永久存储。
- 缓存键加入规范化后的 `customTopic`，防止不同输入共享错误结果。
- 生成 prompt 继续使用既有格式、玩家偏好和问题数量约束，只把专题词替换成 `customTopic`。
- 自定义生成不能获得 4–5 条合格题目时，服务端返回当前 `topicId` 对应的预设题，并带 `customFallback: true`；这不是“自定义专题已生成”的结果。

## 失败与兜底

当 `customFallback` 为真，前端在题目列表上方显示：

> 派蒙暂时没想出来，请换个关键词再试。

下方继续显示当前地区、当前已选预设专题的五个预设问题，使功能在 API、模型或生成校验不可用时仍可继续使用。

普通预设专题的原有 fallback 文案和行为不变。

## 状态边界

- 自定义专题只影响“让派蒙想几个问题”的生成上下文；点击生成题并提交时，仍由当前地区传递 `activeAskRegion`，所以中央徽记与问答区上下文保持一致。
- 手动输入聊天框的问题仍清除问答区地区上下文，剧透确认仍保留当前问答上下文。
- 自定义词不会变成地区、专题颜色或新的长期 catalog 条目。

## 验证

- Schema/route：接受有效 `customTopic`，拒绝空白、过短和超长输入；仍拒绝未知 `topicId`。
- Generator：确认 prompt 使用自定义词，缓存键区分不同自定义词，失败时回退到当前预设专题并标识 `customFallback`。
- UI 源码测试：确认自定义选择卡、输入框、Tab 补全、失败提示和快速提问路径存在。
- 运行相关 Vitest、`npm run typecheck` 与 `npm run build`。
