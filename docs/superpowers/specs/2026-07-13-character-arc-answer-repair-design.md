# 人物变化类回答污染与跑题修复设计

## 问题

“问派蒙”收到“婕德经历了怎么的变化？”一类人物成长问题时，可能出现两种异常：

- 把“婕德经历了”整体识别为人物名，导致检索失败并返回资料不足。
- 即使识别出婕德，也可能选中带有重复站点标题、导航文字、HTML 实体或连续角色台词的低质量网页片段。模型调用失败时，确定性兜底会直接拼接这些片段，形成“旅行者创作平台……”和 `&hellip;` 泄漏的乱回答。

这是问题理解、证据质量控制和失败兜底共同造成的链路问题，不应通过硬编码婕德答案解决。

## 目标

- 正确理解“某角色经历了怎样／怎么的变化、成长或转变”这类问法，并提取纯净角色名。
- 优先检索能覆盖人物经历、转折和结局的剧情资料，而不是仅命中单句台词或玩法页面。
- 在进入模型和引用区之前，清除或拒绝网页模板噪音、未解码实体和无上下文台词堆。
- 模型失败时不再把外部网页原文直接拼成答案；证据不足就明确说明边界。
- 保持现有剧透控制、引用编号、语言偏好和可信来源策略。

## 推荐方案

### 1. 人物变化意图与实体提取

在规则优先的问题理解中识别下列通用句式：

- `X 经历了怎样／怎么的变化`
- `X 有什么／有何成长`
- `X 后来发生了什么变化`
- `X 是如何转变的`

这些问法归入剧情／人物经历意图，实体只保留 `X`。原问题中的“怎么的”虽然不规范，也应作为常见口语或输入错误兼容。

搜索计划在原问题之外增加人物弧线导向的查询，例如 `X 剧情 经历`、`X 结局 变化`，让证据覆盖起点、关键转折和最终状态。

### 2. 统一网页文本清洗

扩展共享证据清洗逻辑：

- 解码常见命名及数字 HTML 实体，包括 `&hellip;`、`&amp;`、`&quot;` 等。
- 压缩连续重复的站点标题、页面标题和模板短语。
- 识别高密度导航文字、编辑控件、`Created with Sketch` 等页面框架噪音。
- 识别连续“角色名：台词”构成的无上下文对话堆；它可以作为原始资料，但不能独立充当人物变化结论。

网页正文抽取只有在质量分数高于搜索摘要时才能替换摘要，避免“补全文本”反而把干净摘要换成整页导航。

### 3. 证据选择与回答生成

证据选择阶段拒绝以下内容：

- 主要内容是重复站点名或导航模板。
- 清洗后信息量过低。
- 与剧情人物问题不匹配的卡牌、数值或玩法页面。
- 只有零散台词、无法支撑变化过程的片段。

正常生成时，提示模型按照“初始状态 → 关键经历 → 认知或关系转折 → 最终状态”的顺序概括人物变化，并让每个关键事实对应可用引用。

### 4. 安全失败兜底

取消开放式剧情问题中“直接拼接外部网页片段”的确定性兜底：

- 受控知识具备结构化结论时，可以继续生成简短兜底回答。
- 只有外部片段且模型失败时，返回明确的资料边界提示，不展示原始网页文本。
- 任何兜底结果都必须再次通过网页噪音和 HTML 实体检查。

这样即使上游模型或网络临时失败，也不会再次出现站点标题、原始台词和实体字符泄漏。

## 预期回答形态

对婕德问题，系统应依据检索资料概括：她在失去父亲后渴望归属，加入塔尼特并把芭别尔视为家人；在被利用和陷害后认清虚假亲情，最终拒绝继续被部族身份支配，决定以自己的名字选择道路。回答可以指出她变得更独立清醒，同时仍带有失去家人与遭遇背叛留下的创伤。

这只是回归验收样例，不写入生产代码，也不作为婕德专属模板。

## 测试与验收

- “婕德经历了怎么的变化？”提取实体为“婕德”，而不是“婕德经历了”。
- “婕德经历了怎样的变化？”被识别为剧情／人物经历问题。
- 搜索计划包含人物名锚定的经历、变化或结局查询。
- `&hellip;` 等实体被正确解码，最终回答中不出现原始 HTML 实体。
- 重复“旅行者创作平台-观测枢-原神wiki”和导航密集片段被拒绝。
- 连续角色台词不能单独触发确定性外部证据回答。
- 模型失败且外部证据肮脏时，只返回安全边界提示，不回显网页原文。
- 正常模型路径能根据多阶段剧情证据产出连贯、有引用的人物变化总结。
- 运行相关单元测试、全量测试、类型检查、生产构建和一次在线婕德回归。

## 范围外

- 不新增婕德专属知识库或硬编码答案。
- 不重做回答卡片视觉样式。
- 不降低现有剧透门槛，也不移除引用和证据边界提示。
- 不以单个 Wiki 页面替代现有多来源检索策略。
