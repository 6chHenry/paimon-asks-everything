# 问派蒙地区联动设计

## 目标

当玩家通过“问派蒙”侧栏选择地区和专题时，让问答区显式继承该地区的旅行上下文：派蒙空状态图标切换为对应地区徽记，同时保留长答案、引用与考据记录的高可读性。

## 交互

1. 选择右侧地区后，空状态“派蒙在这儿”上方立即预览该地区徽记，并出现一条小型旅行笔记提示，例如“派蒙翻出了「璃月」的旅行笔记”。
2. 点击该地区专题的问题卡时，提交动作附带 `askedRegion`；该值成为当前问答轮次的 `activeAskRegion`。
3. 加载、考据记录和回答上方保留一枚紧凑地区徽记与旅行笔记提示，直到用户通过输入框提交新的手动问题。
4. 手动输入问题不携带地区上下文，提交后恢复默认派蒙罗盘和默认配色。剧透确认沿用原问题的 `activeAskRegion`，不会重置它。

## 视觉与可读性

- 页面不使用整页换色，也不改变正文、输入框、引用卡或考据记录的底色。
- 地区色只作用于问答容器的一条 3px 内侧强调线、徽记的低透明光晕、加载卡边框，以及旅行笔记小标签。
- 文本继续使用 `--ink` 与现有浅色背景；地区色只作为装饰和边界，不能作为正文文字颜色。
- 已有八个地区的主题色变量复用到问答上下文，默认状态不加地区色。

## 彩蛋

旅行笔记提示是唯一新增彩蛋。它不虚构剧情事实，不影响回答内容或资料来源，也不在用户没有选择侧栏地区时显示。

## 实现边界

- 不更改聊天 API、生成器、事件持久化或隐私数据。
- 只在客户端新增 `activeAskRegion` 与地区预览状态；问题卡调用现有 `submitQuestion` 时传递地区参数。
- 使用已接入的游戏内地区徽记 URL；默认状态继续使用 `/compass-mark.svg`。

## 验证

- 页面源码测试验证：问题卡向 `submitQuestion` 传递 `region`、空状态使用地区图标、手动提交清除地区上下文、地区 CSS 变量存在。
- 运行 `npm test -- tests/ui-redesign-source.test.ts`、`npm run typecheck` 与 `npm run build`。
