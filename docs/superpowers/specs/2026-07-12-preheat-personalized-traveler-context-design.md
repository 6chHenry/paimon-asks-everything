# 版本预热页旅行者状态个性化设计

## 背景

版本预热页当前允许用户选择最新完成的地区主线、玩家身份和回答关注点，但三者对结果的影响不对等：地区进度已经控制剧情内容的可见边界，玩家身份虽然会传给预热接口，却尚未实际参与结果编排，关注点也只保存在偏好设置中。用户难以从结果中感知不同组合带来的差异。

本次改造将地区下拉菜单替换为可直接点击的地区按钮，并通过稳定、可测试的规则组合“地区 × 身份 × 关注点 × 回顾深度”，即时调整预热结果的内容编排。事实内容、证据边界和剧透控制保持不变。

## 目标

- 用户无需展开下拉菜单即可直接选择最新完成的地区主线。
- 切换地区、身份或关注点后，已展开的预热结果立即刷新。
- 不同组合在模块顺序、默认焦点、展示数量、解释深度和推荐问题上呈现可验证差异。
- 个性化只改变允许展示内容的编排方式，不改变事实，也不越过地区进度和回顾深度决定的剧透边界。
- 设置区显示当前组合摘要，但结果区不出现“为你生成”或类似的个性化导语。

## 非目标

- 不使用 AI 实时生成个性化内容。
- 不为每一种完整组合手写独立页面或配置。
- 不重写现有知识条目、神之心时间线或关系图数据。
- 不改变“已过剧情回顾 / 完整考据”对内容边界的既有定义。
- 不扩展新的玩家身份、关注点或地区枚举。

## 交互设计

### 地区选择

左侧“最新完成主线”卡片不再使用 `<select>`。改为按主线顺序排列的按钮组：未知/未确定、蒙德、璃月、稻妻、须弥、枫丹、纳塔、挪德卡莱。

每个按钮显示本地化地区名称。当前选中项使用明确的背景、边线和文字对比度表达选中状态；装饰性色彩不得降低标签可读性。按钮组在桌面端保持清晰的横向节奏，在窄屏自动换行，并提供可见的键盘焦点状态与 `aria-pressed`。

### 身份与关注点

玩家身份保持五选一，关注点保持可多选。设置区顶部或摘要栏显示当前组合，例如“须弥之后 · 剧情关注者 · 角色 / 剧情”，用于确认状态。该摘要不是结果导语，不在结果区重复出现。

### 即时更新

用户切换地区、身份或关注点后：

1. 设置区选中态与组合摘要立即更新。
2. 若结果尚未展开，只更新偏好；首次展开时按最新组合加载。
3. 若结果已经展开，自动请求最新组合结果。
4. 刷新期间保留当前结果与页面滚动位置，并显示轻量的“正在重新整理路线”状态。
5. 请求失败时保留上一份结果并提供重试提示，不将结果区清空。
6. 快速连续切换时取消旧请求，只允许最后一次选择的结果生效。

## 个性化规则

采用正交规则组合：地区进度、玩家身份、关注点和回顾深度分别贡献约束或权重，再由统一规则组合器产出展示策略。不得维护“地区 × 身份 × 关注点”的完整笛卡尔积配置表。

### 地区进度

地区进度继续作为剧情可见性的硬边界，并决定默认时间线起点。任何身份与关注点规则都只能在已经通过进度过滤的内容中排序和裁剪，不能解锁后续地区条目。

### 回顾深度

“已过剧情回顾”继续限制后续地区与争议内容；“完整考据”继续允许已实装后续地区、文本暗示与争议边界。回顾深度先决定候选内容范围，个性化规则再处理候选内容。

### 玩家身份

| 身份 | 编排策略 |
| --- | --- |
| 新玩家 | 阵营和术语前置；减少一次展示的信息量；优先基础关系与低剧透问题。 |
| 回归玩家 | 跳过通用常识；突出所选地区之后到当前版本之间的关键断层。 |
| 剧情关注者 | 时间线、人物动机、证据与伏笔优先；展示更完整的关联问题。 |
| 玩法 / 探索 | 世界任务、地区文本、场景线索和探索相关内容优先。 |
| 轻量玩家 | 只保留核心事件与版本卖点；默认展示更短的结果和直接问题。 |

### 回答关注点

| 关注点 | 权重策略 |
| --- | --- |
| 剧情 | 提高事件链、因果和伏笔相关内容与问题的优先级。 |
| 角色 | 提高人物关系、立场和角色问题的优先级，并选择合适的关系图焦点。 |
| 玩法 / 探索 | 提高地区探索、世界文本和玩法线索的优先级。 |
| 版本概览 | 提高关键事件摘要、版本衔接和核心问题的优先级。 |

多关注点采用固定枚举顺序参与评分，不依赖用户的点击先后。相同输入必须得到稳定、可复现的输出。

### 组合后的展示策略

规则组合器返回明确的展示策略，至少覆盖：

- 结果模块排列顺序；
- 各模块默认展开或收起状态；
- 默认选中的时间线节点；
- 默认关系图及人物或阵营焦点；
- 各模块展示条目数量；
- 推荐问题的筛选与排序。

例如：

- “须弥 × 新玩家 × 剧情”将术语和基础事件前置。
- “须弥 × 剧情关注者 × 角色”将人物关系、动机和伏笔前置。
- “须弥 × 轻量玩家 × 版本概览”减少展示条目，优先快速摘要与核心问题。

结果区不增加个性化导语。差异通过真实的编排结果表现，而不是仅替换标题或选中样式。

## 架构与数据流

前端将 `profile`、`progress`、`focus`、`depth`、`topicId` 和 `language` 一并传给 `/api/preheat`。其中多个关注点使用稳定、可校验的序列化格式，接口解析后恢复为去重且按领域枚举排序的数组。

预热服务先沿用现有逻辑完成主题选择、剧透过滤、时间线本地化和关系图可见性处理，再调用独立的个性化规则组合器。组合器只接收已经允许展示的内容以及用户偏好，返回展示策略和排好序的结果，不负责事实判断或剧透解锁。

页面根据接口返回的展示策略设置默认时间线节点、默认关系图焦点、模块顺序、展开状态、条目数量和推荐问题。前端不复制服务端的评分逻辑，避免同一组合在两端产生不同结果。

## 状态与错误处理

- 偏好继续通过现有 `PreferencesProvider` 保存，保持与其他页面的一致性。
- 首次进入页面时沿用已保存的地区、身份与关注点。
- 请求以最新偏好快照为准，并通过 `AbortController` 取消过期请求。
- 后台事件记录失败不影响页面使用。
- 个性化规则找不到特定匹配内容时回退到稳定的通用排序；不得因此返回空白模块。
- 非法身份、地区或关注点由查询 schema 拒绝并返回 `400`。

## 可访问性与响应式要求

- 地区按钮使用原生 `button`，并通过 `aria-pressed` 表达状态。
- 所有选中态不能只依赖颜色；同时使用边线、背景或字重差异。
- 键盘用户可以按正常 Tab 顺序访问全部地区按钮，焦点轮廓清晰。
- 按钮触控区域满足现有站点移动端控件尺寸基线。
- 中英文标签在桌面与窄屏下均不溢出或遮挡。
- 自动刷新不得抢占焦点或强制滚动结果区。

## 测试与验收

### 规则单元测试

- 同一地区、不同身份的展示策略至少在模块顺序、展示数量或默认节点之一产生差异。
- 同一身份、不同关注点的推荐问题和默认关系图焦点产生对应差异。
- 多关注点组合与点击顺序无关，输出稳定。
- 身份与关注点不能使超过地区进度的内容可见。
- 无特定匹配时使用通用排序且模块不为空。

### 接口测试

- `/api/preheat` 正确接收身份、地区和多个关注点。
- 无效关注点返回 `400`。
- 缺少关注点时使用既有默认偏好，保持向后兼容。
- 返回数据包含页面所需的展示策略。

### 页面验收

- 地区选择区不再存在下拉菜单，全部地区均可直接点击。
- 当前地区选中态、键盘焦点和移动端换行清晰可用。
- 切换任一设置后，已展开结果自动刷新且页面位置不跳动。
- 设置区组合摘要同步更新，结果区不存在个性化导语。
- 三个样例组合在模块顺序、默认焦点、条目数量或推荐问题上呈现可验证差异。
- 中英文界面、类型检查、完整测试与生产构建全部通过。
