# 回答能力整合设计

日期：2026-07-14  
基线分支：`codex/answer-clue-heading-layout`  
目标分支：`codex/answer-capability-integration`

## 1. 背景与结论

仓库目前存在两个独立的回答方向：

- `codex/answer-clue-heading-layout`（方向 A）已经完成角色成长意图识别、网页文本清洗、实体相关性约束、证据排序、生成后质量检查与安全边界处理。
- `codex/answer-retrieval-architecture`（方向 B）增加了低剧透原子事实、分层搜索路由、后端故障隔离、核验状态和受限的模型已有知识兜底。

同环境对比显示，两边的固定能力测试均为 11/12，但真实质量存在明显偏科：

- 方向 A 能阻止婕德问题输出导航文本和人物列表，但在实时证据不充分时只返回安全边界。
- 方向 B 能依靠本地原子事实快速、稳定地回答冰之女皇与执行官的关系，但面对婕德问题会把网页站点标题和无关列表错误标记为 `verified`。
- 两边的中文回归补课仍可能混入网页导航或无关长摘录；中文机关提示分别出现拒答或答非所问。

因此不选择整分支覆盖或直接合并。目标方案以方向 A 为能力与安全底座，只移植方向 B 中职责独立、经过验证的能力。

## 2. 目标

1. 保留方向 A 的角色意图识别、网页清洗、证据准入与安全边界能力。
2. 增加本地原子事实优先路径，使稳定基础关系不依赖实时网页搜索。
3. 使用分层搜索路由减少宽泛搜索、重复结果和单后端故障影响。
4. 为每次回答提供准确的 `verified`、`partially_verified` 或 `model_knowledge` 状态。
5. 只在稳定基础常识上允许明确标注的模型已有知识兜底。
6. 将固定能力测试提升到 12/12，并防止中文回答暴露网页导航、站点标题和实体列表。

## 3. 非目标

- 不重写方向 A 的问题理解、实体词典、网页文本质量或证据质量模块。
- 不把模型已有知识当作剧情梗概、角色成长、结局或版本现状的事实来源。
- 不以扩大通用搜索数量来提高召回率。
- 不在本次改动中建立完整的外部知识库或向量数据库。
- 不把所有社区分析升级为可信事实，也不改变现有剧透确认策略。

## 4. 方案选择

### 采用：选择性移植

从方向 A 建立目标分支，只引入方向 B 的独立模块，并通过方向 A 的接口接入。

该方案具备以下优势：

- 方向 A 的 338 项测试与证据治理逻辑可以原样保留。
- 每项新增能力都能独立提交、验证和回滚。
- 搜索调度与证据裁决保持职责分离。
- 不需要在合并后重新找回被方向 B 简化掉的质量检查。

### 不采用：双流程外层调度

在 A 外部先运行一整套 B，再决定是否调用 A，会产生重复问题理解、重复生成和两套不一致的核验语义。

### 不采用：整体合并 B 后补回 A

两个方向在 `external-search.ts`、`generation.ts`、`agent.ts` 等核心路径上高度重叠。整体合并容易遗漏方向 A 的角色成长与脏网页回归覆盖，风险不可控。

## 5. 总体数据流

```text
用户问题
  ↓
A：安全分类、实体识别、意图识别、查询规划
  ↓
本地受控知识与低剧透原子事实检索
  ├─ 证据覆盖充分 → 受控生成 → verified
  ↓ 证据不足
分层搜索路由
  ├─ 直接资料源层：受信 Wiki / 可解析资料页
  └─ 仍不足时：通用网页搜索层
  ↓
A：网页解码与清洗 → 实体相关性门控 → 证据质量与阶段覆盖检查
  ├─ 完整覆盖 → 证据约束生成 → verified
  ├─ 仅覆盖部分 → 只回答受支持部分 → partially_verified
  ↓ 无可用证据
稳定基础事实策略检查
  ├─ 允许 → 模型已有知识暂定回答 → model_knowledge
  └─ 禁止 → A 的安全边界回答
```

搜索路由只决定“何时调用哪个后端”，不决定证据是否可信。所有外部候选都必须经过方向 A 的清洗、实体门控和证据质量检查。

## 6. 组件与文件边界

### 6.1 完整保留方向 A

以下模块继续作为唯一实现，不使用方向 B 的版本覆盖：

- `lib/question-understanding.ts`
- `lib/entity-lexicon.ts`
- `lib/web-text-quality.ts`
- `lib/evidence-quality.ts`
- `lib/answer-quality.ts`
- `lib/search-result-url.ts`
- `lib/external-search.ts` 中的查询生成、页面清洗、实体相关性和证据筛选语义
- 方向 A 现有全部测试

### 6.2 从方向 B 引入的独立模块

- `data/faction-knowledge.ts`
- `lib/search-router.ts`
- `VerificationStatus` 领域类型
- 回答卡上的核验状态提示
- 搜索后端尝试记录、超时记录和单后端故障隔离

### 6.3 需要按 A 的规则改造后引入

#### `lib/model-knowledge.ts`

- 保留独立模型调用与结构化解析。
- 策略允许范围缩小到稳定身份、组织从属、基础人物关系和非时效常识。
- 禁止角色成长、剧情梗概、剧情结局、版本状态、角色实装、卡池、泄露、测试服内容和强否定断言。
- 成功结果固定为 `model_knowledge`、低置信度、空引用。

#### `lib/external-search.ts`

- 使用 `search-router.ts` 编排直接资料源层和通用搜索层。
- 每层内部允许并行，单后端失败不终止其他后端。
- 只有方向 A 的证据充分性函数可以触发提前停止。
- 查询数量保持有界；关系题和角色成长题继续使用 A 的专用查询规划。

#### `lib/generation.ts`

- 在外部搜索前增加本地证据充分性判断。
- 本地充分性不能只检查 `atomic-fact` 标签，还要根据问题意图检查受控证据覆盖。
- 所有外部证据继续使用 A 的生成前筛选、生成后验证和安全回退。
- 不允许脏引用通过确定性摘录生成器绕开最终质量检查。

#### `lib/agent.ts`

- 按最终可用证据和声明覆盖情况设置核验状态。
- 只有通过 A 准入的引用才能参与 `verified` 判断。
- 模型已有知识兜底位于 A 的证据筛选之后，并受问题类型策略限制。
- 剧情与角色成长问题证据不足时继续返回安全边界。

## 7. 本地证据充分性

本地证据优先用于避免已有答案仍触发宽泛网页搜索。

### 原子事实

低剧透、已审阅、与核心实体及意图一致的原子事实可以单条形成充分证据。例如冰之女皇与执行官的组织关系。

### 回归补课

当本地受控条目已经覆盖用户进度、目标背景和主要桥接概念时，直接生成回答，不再追加网页考据、植物、饮食或百科页面。

### 机关提示

当本地受控条目已经提供观察层、机制层和执行层提示时，直接返回分层提示。用户没有给出具体机关名称时，不搜索并拼接某个敌人或机关的专用战斗机制。

### 角色成长

角色成长不能由单条人物资料卡或实体列表判定充分。必须覆盖起点、关键转折和结果；否则进入外部证据流程或安全边界。

## 8. 核验状态

### `verified`

满足以下任一条件：

- 使用已审阅、低剧透兼容且与问题直接相关的本地受控事实；
- 回答中的关键声明全部被方向 A 接受的干净、相关外部证据覆盖。

来源域名属于白名单不是充分条件。页面导航、站点标题、人物列表或仅偶然提到实体的页面不能产生 `verified`。

### `partially_verified`

- 仅部分问题得到可靠证据支持；
- 正文只输出受支持部分，并明确未覆盖边界；
- 不得使用模型知识补全剩余剧情后仍标记为部分核验。

### `model_knowledge`

- 外部核验不可用或没有合格证据；
- 问题通过稳定基础事实策略；
- 回答明确标为暂定、低置信度且不展示引用。

### 安全边界回答

不属于以上状态。核验状态字段只适用于 `answered` 结果；`insufficient_evidence`、`refused` 和 `spoiler_confirmation_required` 使用空核验状态。安全边界表示系统没有足够证据形成答案，不展示被拒绝的污染引用，也不暗示已经完成核验。

## 9. 模型已有知识策略

### 允许

- 稳定的人物身份
- 明确的组织从属
- 基础人物关系
- 不依赖当前版本的常识性设定

### 禁止

- 角色成长与人物弧光
- 长篇剧情梗概、结局与幕后真相
- 当前版本、角色是否实装、卡池和活动状态
- 官方尚未公开的内容、泄露与测试服信息
- “从未”“一定不是”“已经证实不存在”等强否定断言

模型已有知识不能引用外部来源 ID，不能伪造来源名称，不能升级为 `verified` 或 `partially_verified`。

## 10. 搜索路由与错误处理

- 直接资料源层先执行；只有证据仍不充分时才进入通用搜索层。
- 同层后端可以并行，结果按规范化 URL、标题和正文指纹去重。
- 单个后端超时或失败只产生诊断记录，不中断整次回答。
- 请求取消后不启动下一层，也不继续模型兜底。
- 模型接口失败时回到方向 A 的确定性受控回答或安全边界。
- 流式回答在核验状态确定前不能发送最终 `verified` 标记。
- 所有失败路径都必须保持引用与正文一致，不能留下半个回答或孤立引用。

## 11. 内容质量要求

最终正文和展示引用不得包含：

- 重复站点名称或页面标题
- Wikipedia、Wiki 或论坛导航菜单
- 大段人物分类列表
- 未解码 HTML 实体
- 无上下文的角色对话堆叠
- 与核心实体无关的页面正文
- 搜索引擎重定向或跟踪 URL

最终答案必须再次通过方向 A 的网页噪声与声明质量检查。即使模型生成成功，命中上述模式也要修复或进入安全边界。

## 12. 测试策略

### 12.1 保留方向 A 的回归覆盖

方向 A 的 338 项测试必须全部保留并通过，尤其包括：

- 角色成长意图与错字变体
- 网页实体解码和导航噪声识别
- 对话堆叠、实体列表和无关页面拒绝
- 角色成长阶段覆盖和强制查询
- 确定性安全边界与引用清洗

### 12.2 新增独立模块测试

- 原子事实的低剧透检索和同语言优先
- 搜索分层、充分证据提前停止、后端故障隔离和结果去重
- 模型已有知识允许与禁止矩阵
- 三种核验状态的 API 与 UI 一致性

### 12.3 核心端到端回归

#### 婕德

标准问法与错字变体都必须识别为 `character_arc`。

- 干净证据覆盖起点、归属需求、塔尼特操控与背叛、夺回自我身份时，输出结构完整的 `deep_story`。
- 证据不完整时返回安全边界。
- 禁止 `minimal_catch_up`、页面导航、实体列表和错误的 `verified`。

#### 冰之女皇

- 低剧透请求直接使用本地原子事实。
- 返回 `verified`、高置信度和一条本地引用。
- 不启动外部搜索。
- 不加入“丑角创立愚人众”或“与女皇只是合作伙伴”等社区推测。

#### 模型已有知识边界

- 雷电将军与雷电影的稳定关系在所有证据路线为空时允许 `model_knowledge`。
- “爱可菲现在实装了吗”不得使用模型已有知识。
- 模型暂定回答必须为空引用且低置信度。

### 12.4 固定能力测试

仓库内 12 道能力测试必须达到 12/12，并增加正文质量断言：

- 中文回归补课只使用充分的本地受控背景，不混入植物、饮食、雷穆斯长摘录或百科导航。
- 中文机关提示使用本地三层通用提示，不拒答，也不返回具体敌人战斗机制。
- 英文补课、桑多涅、剧透门控、安全拒绝、Liben 和关系边界不低于方向 A 的行为。

### 12.5 真实环境验收

- 固定 12 题完整运行一次。
- 婕德标准问法、错字变体和冰之女皇问题各重复两次。
- 记录状态、模式、核验状态、引用、原始答案、耗时和重复稳定性。
- 不以 HTTP 200 或引用数量代替人工内容检查。

## 13. 交付与提交边界

实施按独立能力拆分提交：

1. 本地原子事实与本地证据充分性。
2. 分层搜索路由与诊断。
3. 核验状态与受限模型已有知识兜底。
4. 固定能力题正文质量修复。
5. 跨架构回归与文档更新。

每个提交完成对应聚焦测试；最终运行全部单元测试、类型检查、生产构建和真实 API 验收。未经完整验证不合入 `main`。

## 14. 成功标准

- 方向 A 的角色成长与网页质量能力无回退。
- 冰之女皇问题稳定使用本地事实，正确、无社区漂移且显著降低延迟。
- 婕德问题不再出现站点标题、导航列表、错误回答模式或虚假 `verified`。
- 固定能力测试达到 12/12，中文补课与中文机关提示通过人工内容检查。
- `verified` 只表示真实证据覆盖，模型已有知识不会伪装成已核验事实。
- 搜索后端失败不会拖垮回答，取消和超时路径不留下不一致状态。
