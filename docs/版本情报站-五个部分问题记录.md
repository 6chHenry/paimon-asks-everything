# 版本情报站：五个部分的问题记录

> 这是一份阶段性问题记录，不是最终设计方案。
>
> 当前阶段只记录现状、主观感受、问题假设和后续需要确认的方向；暂不直接修改页面实现。

## 0. 产品整体结构

网站目前分为五个部分：

1. **版本情报**：首页，负责第一印象、版本氛围和主要内容入口。
2. **版本预热**：围绕当前版本主题进行主动引导和内容预热。
3. **问派蒙**：玩家向派蒙提问，获得版本理解和资料解释。
4. **能力预览**：用于测试问答、证据链和能力表现，暂时不作为重点体验打磨对象。
5. **发行洞察**：面向开发者 / 制作组，把玩家问题和互动转化为发行建议。

整体目标不是把五个页面做成同一种工具界面，而是让它们分别承担不同的叙事角色：

- 版本情报负责“把人吸引进来”；
- 版本预热负责“让人产生兴趣并继续探索”；
- 问派蒙负责“在具体疑问出现时陪伴解释”；
- 能力预览负责“验证系统能力”；
- 发行洞察负责“把玩家侧信号翻译成制作组可以行动的建议”。

## 1. 版本情报：首页

### 当前做法

- 首页首先展示版本倒计时。
- 倒计时下面是 PV 预览。
- 页面下方还放置了至冬关系图谱的入口和完整图谱。

### 当前感受 / 问题

- 首页需要在进入后立刻引人入胜；目前“倒计时 + PV 预览”是明确的抓手，但还需要确认它们是否形成了足够强的第一屏叙事。
- 至冬关系图谱放在首页是有价值的，因为它能代表产品的核心能力和至冬版本的复杂度；但当前图谱在视觉上显得不够精致，整体有“功能已经完成、呈现还像 Demo”的感觉。
- 关系图谱目前更像一个被放在首页下方的功能模块，尚未完全成为首页叙事的一部分。
- 首页内容层次可能存在竞争：倒计时、PV、角色内容、关系图入口、完整图谱都在争夺注意力，需要重新确认主次和阅读节奏。
- 需要区分“首页用于吸引和引导”与“关系图页面用于深度探索”这两个目标，避免首页直接承载过多复杂交互。

### 初步判断

首页的问题不只是“图谱样式不够好看”，还包括：

1. 图谱在首页中的角色没有被充分解释；
2. 首页的视觉焦点和内容顺序还可以进一步收束；
3. 图谱的节点、连线、标签、证据等级和详情面板之间还没有形成足够统一的视觉语言；
4. 首页可能需要一个更强的“悬念 / 发现 / 继续探索”过渡，而不只是多个模块纵向排列。

### 后续需要细化的问题

- 首页第一屏最终要让用户先感受到什么：版本将至的紧迫感、至冬的悬念，还是派蒙作为向导的陪伴感？
- PV 是首页的主角，还是关系图谱应该成为更强的核心视觉？
- 关系图谱在首页应该保留完整交互、只做高质量预览，还是改造成一个带悬念的“可探索入口”？
- 关系图谱需要重点优化的是视觉精致度、信息层级、交互反馈，还是内容结构本身？

### 已确认方向

- 首页第一感受同时包含两条线索：
  - **紧迫感**：通过倒计时让用户意识到版本正在靠近；
  - **悬念感**：通过至冬的关系、人物和伏笔让用户产生继续探索的动机。
- 后续设计不能把倒计时和关系图谱当成两个互不相关的模块，而要让它们共同组成“版本将至、但真相仍未完全展开”的首页叙事。

### 新增内容约束

- 版本预热必须保留一部分“等待至冬版本开启后揭晓”的内容，不能把所有悬念在预热阶段一次性解释完。
- 页面要让玩家明确看到三种边界：已经确认的事实、可以继续推演的线索、必须等待版本开启的未知信息。
- 悬念不能只靠一句“敬请期待”，而应通过封存节点、未完成事件链、被遮蔽的证据和明确的揭晓条件来形成可感知的期待。

### 已确认页面结构方向

- 版本预热采用**断点事件链**作为主结构：
  - 已确认事件；
  - 可以继续追踪的文本暗示；
  - 明确展示的未解断点。
- 不把未知内容做成无意义的空白，而要让玩家看到断点出现在哪里、前面的线索如何指向它，以及需要等待什么条件才能继续揭晓。
- 该方向优先复用现有时间线、关系图和证据等级，仅通过内容编排、节点文案和锁定状态增强悬念冲击力。
- 未解断点采用**明示问题、隐藏答案**的方式：玩家可以看到正在等待揭晓的具体问题、前置线索和解锁条件，但看不到最终答案。

## 2. 版本预热

### 当前做法

- 当前版本预热主要围绕一个主题展开：七国神之心。
- 页面已经具备预热主题、内容深度和关系 / 时间线等能力基础。

### 当前感受 / 问题

- 目前只有“七国神之心”一个主题，内容面显得偏窄，尚未充分体现版本预热可以承载的丰富度。
- 页面需要进一步明确“预热”与“问派蒙”的差异：预热应该主动制造兴趣和理解路径，而不是仅仅把资料换一种方式陈列出来。
- 需要判断一个主题是否足以支撑完整页面体验，还是应该提供多个并列的预热主题入口。

### 初步判断

版本预热需要从“单一专题展示”进一步明确为“围绕版本卖点组织探索路径”的页面。七国神之心可以继续保留为核心样板，但可能需要补充其他主题，或者至少让一个主题内部形成更完整的分支。

### 后续需要细化的问题

- 后续主题应优先选择世界观悬念、角色关系、剧情伏笔，还是版本玩法 / 内容卖点？
- 预热主题是由制作方预先编排，还是允许根据玩家画像展示不同入口？
- 版本预热的核心成功标准是“用户愿意继续点开”，还是“用户能形成一个清晰的版本理解框架”？

## 3. 问派蒙

### 当前判断

- 当前页面整体体验已经相对可接受。
- 这部分暂不列为本轮重点改造对象。

### 保留事项

- 后续如果首页和版本预热的信息架构发生变化，需要检查它们是否仍然自然地把用户引导到问派蒙。
- 如果发行洞察继续使用问答和预热数据，也要保持玩家端体验和开发者端洞察之间的概念一致。

## 4. 能力预览

### 当前判断

- 这是用于测试问答、证据链和能力表现的页面。
- 当前阶段可以暂时不做视觉和交互层面的重点完善。

### 本轮边界

- 不把能力预览作为本轮主要设计资源投入方向。
- 除非其他页面调整影响到它的入口或共享组件，否则暂不改动。

## 5. 发行洞察

### 当前定位

- 页面面向开发者 / 制作组，而不是普通玩家。
- 目标是根据玩家问题、预热互动和相关信号，为版本发行提供可执行建议。

### 当前感受 / 问题

- 需要进一步把“发行洞察”从数据展示页提升为真正的发行决策辅助工具。
- 页面不应只告诉开发者“玩家问了什么”，还应帮助他们理解：玩家卡在哪里、为什么会卡、应该补充什么内容、优先级如何、建议如何验证。
- 需要让建议具备证据回溯能力，避免变成没有依据的泛泛而谈。
- 需要进一步明确页面的主要阅读对象和使用场景，例如版本筹备会、内容评审、FAQ 编写、本地化检查或预热复盘。

### 初步判断

发行洞察页面应该围绕“判断 → 证据 → 行动”组织信息，而不只是围绕统计图表组织信息。建议最终至少能回答：

1. 当前最值得关注的玩家理解问题是什么？
2. 这个问题的证据来自哪里，样本是否足够？
3. 它对版本发行有什么风险或机会？
4. 制作组下一步可以采取什么具体动作？
5. 如何判断这个动作是否有效？

### 后续需要细化的问题

- 发行建议的最小行动单位是什么：一条 FAQ、一段预热文案、一个视频选题、一个角色 / 关系说明，还是一个版本内容调整建议？
- 页面应该优先展示“当前最重要的三件事”，还是提供完整的分析工作台？
- 开发者最关心的是内容理解风险、玩家兴趣机会、语言 / 本地化差异，还是版本节奏与预热顺序？
- 建议是否需要支持状态管理，例如“待评审 / 已采纳 / 已验证”？

### 已确认使用场景

- 发行洞察优先服务于**版本筹备会中的真实决策**，不是单纯展示系统能力的 Demo 看板。
- 页面需要帮助制作组在会议中快速判断：当前最值得处理的问题、建议采取的内容动作、证据是否足够，以及后续如何验证效果。
- 因此，发行洞察的核心输出应从“数据概览”转向“可讨论、可采纳、可追踪的发行建议”。

### 方向确认

- 发行洞察按上述真实版本筹备会场景推进，优先完善建议内容、证据解释和行动闭环；UI 只做必要调整。

## 6. 当前优先级

### 第一优先级：版本情报首页

- 重新确认首页第一屏的叙事焦点。
- 提升至冬关系图谱的精致度和辨识度。
- 重新设计首页模块之间的过渡和层级，避免多个模块平铺争夺注意力。

### 第二优先级：版本预热

- 明确单主题与多主题的内容策略。
- 扩充或重新组织预热主题，让它更像主动引导，而不是静态资料页。

### 第三优先级：发行洞察

- 明确开发者使用场景。
- 把数据、证据、判断和行动建议串成完整流程。
- 形成可执行、可回溯、可验证的发行建议表达。

### 暂不优先

- 问派蒙：当前基本可接受，只做联动检查。
- 能力预览：继续作为测试页使用，暂不做重点改造。

## 7. 后续工作方式

下一步不直接进入代码修改，而是按下面的顺序逐项确认：

1. 先细化首页：第一屏目标、关系图角色、首页模块顺序。
2. 再细化关系图：视觉风格、信息层级、交互方式和精致度标准。
3. 再细化版本预热：主题数量、主题选择逻辑和内容结构。
4. 最后细化发行洞察：开发者场景、建议类型、证据链和页面结构。
5. 形成确认后的设计方案，再开始实现和验证。
