# 发行增量实验室 · 面试演示手册

## 一句话定位

> PAIMON 原本能发现玩家关注什么；增量实验室进一步回答：对哪类玩家，在什么时机，使用哪条 PV 或哪种渠道触达，能额外增加多少 D30 留存。

页面入口：`/release-lab`

## 证据边界

- 页面全部结果来自固定随机种子的合成随机实验，不代表真实 PAIMON、达人或展会业务效果。
- 合成数据用于证明数据合同、模型、评估、产品页面和验证方案能够完整运行。
- 真实上线时必须用匿名随机分流日志替换合成数据，并保留未触达 Holdout。
- LLM 只把结构化结果翻译成运营语言，不参与增量数值计算。

## 五分钟演示顺序

### 0:00–0:40 · 从现有 PAIMON 出发

打开“发行洞察”，说明现有能力：

> PAIMON 会根据玩家提问、预热点击和身份信号判断内容热度与理解风险。但“玩家感兴趣”只是相关信号，不能证明给他看某条 PV 会提高留存。

切换到“增量实验”：

> 所以我补了一层增量决策：把动作、对照和 D30 结果记录下来，估计动作相对不做带来的额外变化。

### 0:40–2:20 · PV × 玩家

依次点击“新入坑玩家”和“轻度休闲玩家”。

讲解新入坑玩家：

> 模型比较剧情、角色、玩法三条 PV 和不触达。合成实验中，玩法战斗 PV 对新入坑玩家的 D30 留存增量点估计为 5.54 个百分点，95% 区间为 1.51 到 9.58 个百分点，区间下界超过 1 pp 业务阈值，所以进入小流量验证，并保留 10% Holdout。

讲解轻度休闲玩家：

> 这个人群的最佳候选区间仍跨过阈值，所以系统输出“不触达”。高留存预测不等于值得触达；如果没有可信增量，减少打扰本身也是决策。

指出矩阵：

> 矩阵不是“谁会留存”的响应分数，而是每个 PV 相对不触达对照的百分点变化。第一版使用多处理 T-Learner 和逻辑回归，便于解释和复现。

### 2:20–4:05 · 达人 × 展会

切换“达人 × 展会”。

> 我把问题设计成 2×2 随机实验：对照、仅达人、仅展会、两者都有。这样能分别估计达人、展会和协同项。

指向联合结果：

> 合成实验中，联合组相对对照组的 D30 留存增量为 12.98 个百分点，95% 区间为 11.22 到 14.84。页面再用 Shapley 平均边际贡献分配这部分联合增量：达人约 59.5%，展会约 40.5%。

立即补充边界：

> 这里的百分比只是在分配“联合增量”，不是说全部留存中有 59.5% 来自达人。自然留存仍属于基准水平；Shapley 是分配规则，随机对照才是因果证据。

展示四组表格：

> 路径追踪回答用户从哪里来，2×2 实验回答如果不做会少多少。若展会无法个人随机，我会改用匹配城市 Geo-lift 或分批上线 DID。

### 4:05–5:00 · 方法档案与落地

打开“方法与证据档案”：

> 特征只使用触达前 14 天行为，主标签是触达后 D30 是否留存，防止结果期泄漏。离线除了 AUUC，还用随机日志做策略价值评估；真正上线后仍需小流量 A/B 验证增量 D30 留存、负反馈和 iROAS。

收尾：

> 我没有把 AI 当结论机器。模型负责估计和排序，实验负责证明，运营页面负责把结果变成动作、成本、风险和下一轮验证。

## 达人和展会归因 · 60 秒回答

> 我会分三层做。第一层是追踪链路：达人用独立深链、落地页或兑换码，展会用现场二维码、预约页或票证 ID，把曝光、预约、激活、D7/D30 留存和付费串起来，但这只能说明路径相关。第二层做增量实验：理想情况下设计对照、仅达人、仅展会和两者都有的 2×2 分流，估计两个主效应和协同效应；展会无法个人随机时，使用匹配城市的 Geo-lift 或分批上线 DID。第三层才做长期预算汇总，用实验校准 MMM。最终报告增量用户、增量留存、iROAS 和置信区间。如果一定要分联合效果，我可以用 Shapley 分配协同，但不会把它说成全部留存的真实来源占比。

## 高频追问

### 为什么不用一个模型直接预测谁会留存？

留存模型估计 `P(Y=1|X)`，容易把本来就会留下的人排在最前面。Uplift 估计 `P(Y=1|X,A=a)-P(Y=1|X,A=control)`，目标是找到会因动作而改变的人。

### 为什么第一版用逻辑回归，而不是因果森林或深度模型？

第一版优先验证数据合同、随机对照、标签窗口、离线评估和线上决策闭环。逻辑回归可解释、稳定、容易复现；复杂模型只有在同一冻结评测和线上增量上显著更好时才升级。

### 为什么页面还要保留“不触达”？

不触达是反事实基准，也是一个合法动作。区间跨零、效果低于业务阈值、成本过高或负反馈风险高时，不触达优于强行推荐。

### 没有随机对照怎么办？

先降低结论强度。观察数据可以用倾向评分、回归控制、DID 或双重机器学习构造可比组，但依赖无未观测混杂等假设。下一轮应补随机 Holdout、分批上线或地域实验。

### 当前结果能证明项目真的提升留存吗？

不能。当前数字来自合成实验，只能证明方法和产品闭环可运行。真实业务结论必须来自真实随机流量、预注册指标、足够样本和线上置信区间。

### LLM 在系统里做什么？

LLM 可以抽取评论、PV 和达人内容标签，并把结构化模型结果生成运营解释。留存概率、CATE、置信区间和 Shapley 算术由可复现代码计算，LLM 不修改这些数值。

## 本地演示

```powershell
python -m pip install -r requirements-release-lab.txt
npm run report:release-lab
npm run test:release-lab
npm test -- tests/release-lab.test.ts tests/release-lab-ui.test.ts
npm run dev
```

打开 `http://localhost:3000/release-lab`。

## 演示前检查

- 页面顶部必须显示“合成随机实验”。
- 新入坑玩家应推荐“玩法战斗 PV”。
- 轻度休闲玩家应显示“不触达”。
- 达人和展会分摊比例之和应为 100%。
- 讲占比时必须说“联合增量分摊”，不能说“全部留存来源”。
- 方法档案中应能看到特征窗口、标签窗口、样本量和真实上线替换方案。
